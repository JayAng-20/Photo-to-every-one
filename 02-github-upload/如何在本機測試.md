# 如何在本機測試這個資料夾

這是一個**純靜態網站**，不需要 Node、npm、Homebrew 或任何套件，
只要有 Python 3 就能起一個伺服器。

```bash
python3 -m http.server 8092
```

然後開 <http://127.0.0.1:8092/>。

## 為什麼不需要額外的伺服器腳本

Python 3 的 `http.server` 內建的 MIME 對應已經足夠（本機以 Python 3.9.6 實測）：

| 副檔名 | 回傳的 Content-Type | 夠不夠 |
|---|---|---|
| `.mjs` | `text/javascript` | ✓ 瀏覽器接受這個型別載入 ES module |
| `.js` | `text/javascript` | ✓ |
| `.wasm` | `application/wasm` | ✓ `WebAssembly.instantiateStreaming` 需要這個 |
| `.pack` | `application/octet-stream` | ✓ 本來就是用 `arrayBuffer()` 讀，不看型別 |
| `.css` / `.html` / `.ttf` | `text/css` / `text/html` / `font/ttf` | ✓ |

所以這個資料夾**刻意不放 `serve.py` 或任何 Python 腳本** —— 它是要上傳到 GitHub Pages
的純靜態網站，多放腳本只會混淆。

> `file://` 直接開啟**不會**運作：module worker 與 WebAssembly 的 `fetch()` 會被瀏覽器擋下，
> 一定要透過 HTTP(S) 提供。

## 驗證

開 <http://127.0.0.1:8092/tools/selftest.html> 按「開始測試」，應得到 **13 項 PASS**。

這個資料夾**不含 `test-assets/`**（測試素材不需要上傳），所以 selftest 會抓不到素材。
要在本機完整驗證，請從 `01-final/test-assets/` 複製一份進來再跑，**測完記得移除**
（或直接重跑 `make-deploy.py` 讓它回到乾淨的部署集合）。

## ⚠ 這個資料夾是產生物

任何修改都會在下次重跑 `make-deploy.py` 時被覆蓋。要改請改 `01-final/` 的原始碼。
